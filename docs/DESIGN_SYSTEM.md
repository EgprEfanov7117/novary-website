# NOVARY — дизайн-система

Версия 1.0 · 26 октября 2026 года · Этап: проектирование, без реализации сайта.

Связанный документ: [структура главной страницы и предварительные тексты](HOMEPAGE_STRUCTURE.md).

## 1. Основа бренда и задача интерфейса

NOVARY — современная AI-студия, которая разрабатывает лендинги, многостраничные сайты и небольшие веб-приложения для малого и среднего бизнеса в России. Слоган: **Ideas into digital reality.**

Сайт должен помочь владельцу бизнеса понять три вещи: подходит ли NOVARY под его задачу, как будет организована работа и с чего начать обсуждение. Основное целевое действие — «Обсудить проект». Второе — изучить подходящие услуги и доступные примеры работ.

Премиальность выражается точностью композиции, качеством текста и демонстрацией интерфейсов. Технологичность — ясностью решений и аккуратной обратной связью. Минимализм не должен скрывать стоимость обсуждения, состав услуги, ограничения или следующий шаг.

### Рабочие принципы

1. **Сначала бизнес-задача.** Объяснять, что получит заказчик, а затем — как используется AI.
2. **Один выразительный приём.** Крупный типографический первый экран и спокойная композиция «идея → структура → интерфейс» становятся главным визуальным образом.
3. **Продукт вместо декорации.** Показывать реальные экраны, структуру и сценарии, когда эти материалы существуют.
4. **Сдержанный синий.** Акцент ведёт к действию и обозначает состояние, а не окрашивает весь сайт.
5. **Честная доказательность.** Реальные работы, прозрачный процесс и понятные условия важнее неподтверждённых чисел.
6. **Единая система для всех страниц.** Внутренние страницы наследуют сетку, компоненты, типографику и правила доступности.

### Запреты

- Шаблонный SaaS-набор: симметричный центрированный hero, россыпь одинаковых карточек, тарифы в трёх колонках, декоративные бейджи и логотипы.
- Неон, светящиеся рамки, сетки на фоне, HUD, роботы, мозги, частицы, бесконечно вращающиеся 3D-объекты.
- Градиенты и стеклянные панели в базовом оформлении; исключение — собственное изображение проекта, если этого требует его дизайн.
- Вымышленные клиенты, отзывы, награды, рейтинги, коммерческие результаты, размер команды и стаж.
- Заявления «гарантируем рост продаж», «сделаем любой продукт», «в несколько раз быстрее» без доказательств.
- Курсор нестандартной формы, магнитные кнопки, управление прокруткой вместо пользователя, автоматические карусели.

## 2. Арт-дирекшн и композиция

Направление: **спокойная технологичная студия с сильной типографикой и предметной демонстрацией работы**. Основной фон — Obsidian, отдельные функциональные поверхности — Graphite. Текст преимущественно выровнен влево; центрирование допускается только у небольшого самостоятельного элемента, а не как правило страницы.

На широком экране hero строится из выразительного заголовка на восьми колонках и компактной схемы преобразования идеи в интерфейс на четырёх. Это схема подхода, а не изображение якобы выполненного заказа. Ниже появляется широкое превью настоящей работы либо честно обозначенного концепта — только при наличии готового материала.

Ритм страницы создают разные типы блоков: крупная типографика, изображение проекта, строки услуг, последовательность этапов, открытый текст, вопросы и форма. Не заключать каждый смысловой блок в карточку. Избегать и противоположной крайности: сплошной «газетной» сетки с рамками вокруг каждой строки.

### Самопроверка выбранного направления

| Рассмотренный приём | Решение для NOVARY | Причина |
|---|---|---|
| Тёмный фон с обилием неона | Только заданная палитра и ограниченный синий | Бриф требует технологичности без игровой эстетики |
| AI как огромный декоративный объект | Схема идеи, структуры и интерфейса | Показывает предмет работы студии |
| Одинаковые карточки преимуществ | Услуги в строках, этапы в последовательности, работы крупными превью | Форма отражает содержание |
| Логотипы и счётчики доверия | Только подтверждённые материалы; при их отсутствии — процесс | Новая студия не имитирует масштаб |
| Сложная история на скролле | Обычная читаемая страница | Содержание доступно без анимаций |

### Функциональные расширения

Это служебные цвета состояния, а не новая декоративная палитра.

| Токен | Цвет | Назначение |
|---|---|---|
| accent-hover | `#528AFF` | Наведение на синюю кнопку или ссылку |
| accent-pressed | `#3977F5` | Кратковременное нажатие на синюю кнопку |

| status-error | `#FFB4AB` | Текст и контур ошибки, всегда с пояснением |
| status-success | `#B8D4B1` | Подтверждение выполненного действия, всегда с текстом |

### Проверенные контрастные пары

Расчёт выполнен для сплошных sRGB-цветов по относительной яркости; значения округлены только для отображения. Прозрачность, изображения и новые сочетания требуют отдельной проверки.

| Передний план / фон | Контраст | Правило использования |
|---|---:|---|
| Primary Text / Obsidian | 17,96:1 | Весь основной текст |
| Primary Text / Graphite | 16,49:1 | Текст на поверхности |
| Secondary Text / Obsidian | 6,21:1 | Вспомогательный текст без снижения прозрачности |
| Secondary Text / Graphite | 5,70:1 | Подписи и пояснения полей |
| Electric Blue / Obsidian | 5,08:1 | Ссылки и фокус |
| Electric Blue / Graphite | 4,67:1 | Ссылки на поверхности |
| Obsidian / Electric Blue | 5,08:1 | Подпись основной кнопки |
| Primary Text / Electric Blue | 3,53:1 | Не использовать для обычной подписи кнопки |
| Obsidian / accent-hover | 5,98:1 | Подпись кнопки при наведении |
| Obsidian / accent-pressed | 4,76:1 | Подпись кнопки при нажатии |
| border-control / Graphite | 3,35:1 | Функциональные границы |
| border-subtle / Graphite | 1,41:1 | Только необязательный декор |

Не ослаблять Secondary Text дополнительной прозрачностью. Цвет Borders из брифа недостаточен как единственный способ обнаружить поле или состояние. Поле получает border-control и постоянную подпись.

Ориентир для обычного текста — 4,5:1; для крупного — 3:1. Крупным считается текст от 24 CSS px обычного начертания или примерно от 18,67 CSS px жирного начертания; для этой системы ориентироваться на вес 700. Не применять пониженный порог к мелкому тексту 500/600. Источник: [W3C, контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 4. Правила акцентного синего

- Одна основная синяя кнопка на самостоятельную группу действий. Остальные действия — текстовые или вторичные.
- На одном экране синий занимает ориентировочно до 5–8% площади интерфейса. Это композиционный ориентир, а не ограничение для фокуса и функциональных состояний; изображения проектов считаются отдельно.
- Разрешены: основное действие, подчёркнутая ссылка, фокус, выбранный элемент управления, небольшой смысловой маркер в hero.
- Не разрешены: синий абзац ради украшения, одно случайно выделенное слово в каждом заголовке, синие рамки всех карточек, большой синий фон каждого второго раздела.
- Ссылку отличает подчёркивание, выбранный пункт — дополнительный маркер или подпись. Цвет не несёт смысл в одиночку.
- Успех и ошибка не обозначаются фирменным синим. Для них предусмотрены текст и отдельные служебные цвета.
- Если на экране с проектом уже много синего, не добавлять вокруг него дополнительные акцентные детали.

## 5. Типографика

### Семейства и поддержка русского языка

Брендовая пара: **Space Grotesk** для латинской заголовочной типографики, **Inter** для основного текста и интерфейса.

В стандартной поставке Google Fonts Space Grotesk отсутствует кириллица: [метаданные семейства](https://github.com/google/fonts/blob/main/ofl/spacegrotesk/METADATA.pb). У Inter кириллица есть: [метаданные Inter](https://github.com/google/fonts/blob/main/ofl/inter/METADATA.pb).

Поэтому для русскоязычного сайта фиксируется явное исключение: **русские и смешанные заголовки целиком набираются Inter 500/600**, с той же шкалой и композиционной ролью. Space Grotesk 500 используется для латинского слогана и самостоятельных латинских заголовков. Текстовое написание NOVARY может использовать Space Grotesk как временный wordmark; это не заменяет разработку логотипа.

Не подменять кириллицу похожими латинскими буквами, не подключать неизвестную «кириллическую версию» без проверки, не смешивать семейства по отдельным символам одной фразы. Если появится лицензированная кириллическая версия Space Grotesk, повторно проверить набор и переносы до замены. До этого Inter — предусмотренное решение, а не случайный системный fallback.

### Шкала

Значения: размер / межстрочный интервал в CSS px при стандартном масштабе. В будущей реализации размеры привязать к относительным единицам и пользовательскому масштабу текста.

| Роль | Desktop, от 1200 px | Tablet, 768–1199 px | Mobile, 360–767 px | Вес / трекинг |
|---|---|---|---|---|
| Display, H1 главной | 88 / 94 | 64 / 70 | 40 / 46 | 500; −0,035em desktop, −0,02em mobile |
| H1 внутренних страниц | 64 / 72 | 48 / 56 | 36 / 42 | 500; −0,025em |
| H2 раздела | 48 / 56 | 40 / 48 | 32 / 40 | 500; −0,025em |
| H3 / название работы | 28 / 36 | 26 / 34 | 24 / 32 | 500; −0,015em |
| H4 / подзаголовок | 22 / 30 | 22 / 30 | 20 / 28 | 600; −0,01em |
| Lead, вводный абзац | 22 / 34 | 20 / 32 | 18 / 28 | 400; 0 |
| Body | 18 / 28 | 18 / 28 | 16 / 26 | 400; 0 |
| UI: кнопки, меню, поля | 16 / 24 | 16 / 24 | 16 / 24 | 500; 0 |
| Caption / метаданные | 14 / 22 | 14 / 22 | 14 / 22 | 400; 0 |

На ширине 320–359 px Display уменьшается до 36 / 42. Между опорными размерами допускается плавное изменение Display, H1 и H2 без скачков; основной текст остаётся в заданных диапазонах. Жирный текст в абзаце — 600, без дополнительных цветов.

### Набор и переносы

- На странице один H1; Display — его визуальный стиль на главной, а не отдельный уровень заголовка.
- H2 обозначает самостоятельный раздел, H3 — услугу, работу или вопрос внутри него. Уровни не пропускаются ради размера.
- Ширина обычного абзаца — примерно 45–70 знаков; верхний предел — 75. На телефоне естественно меньше.
- Заголовок hero — 2–4 строки по ширине устройства, без искусственной фиксации переноса для всех экранов.
- Предлоги по возможности удерживать со следующим словом, но не создавать длинных неразрывных фрагментов, ломающих 320 px.
- Не использовать разреженный капс для подписей. Исключение — само название NOVARY.
- Не сжимать буквы и не растягивать текст по ширине. Если заголовок не помещается, менять размер в пределах шкалы, ширину колонки или редактуру.
- Безопасная загрузка шрифтов: текст виден до загрузки, размеры блоков стабильны, локальное размещение файлов с сохранением лицензий — предпочтительный вариант будущей реализации.

## 6. Система отступов

Базовая единица — 4 px; основные композиционные шаги кратны 8 px. Исключения — линии 1 px, фокус 3 px и оптическая корректировка иконки до 2 px.

| Токен | Значение | Типовое применение |
|---|---:|---|
| space-1 | 4 px | Очень тесная связка вспомогательных элементов |
| space-2 | 8 px | Иконка и подпись; label и поле |
| space-3 | 12 px | Категория и название работы |
| space-4 | 16 px | Соседние небольшие элементы; мобильный gutter |
| space-6 | 24 px | Параграфы, внутренний отступ поверхности |
| space-8 | 32 px | Группа действий; блоки внутри раздела |
| space-10 | 40 px | Заголовок раздела и его содержание на mobile |
| space-12 | 48 px | Внутренняя композиционная пауза |
| space-16 | 64 px | Заголовок раздела и содержание на desktop |
| space-24 | 96 px | Пауза между небольшими разделами |
| space-32 | 128 px | Основная пауза между разделами desktop |
| space-40 | 160 px | Исключительная пауза у hero или финального контакта |

Правило близости: подпись ближе к своему полю, чем к соседнему; название проекта ближе к своему превью, чем к следующей работе. Внутри смысловой группы использовать 8–24 px, между группами — 32–64 px.

Вертикальная пауза между завершёнными разделами: desktop 128 px, tablet 96 px, mobile 72 px; у компактного FAQ допустимо 64 px. Это расстояние **от последнего элемента одного раздела до первого элемента следующего**, а не двойная сумма верхнего и нижнего padding. Делитель помещается внутри этой паузы и не увеличивает её автоматически.

## 7. Контейнер, сетка и ширина контента

| Диапазон viewport | Внешнее поле с каждой стороны | Колонки | Межколонник | Навигация |
|---|---:|---:|---:|---|
| 320–767 px | 20 px | 4 | 16 px | Кнопка «Меню» |
| 768–1199 px | 32 px | 8 | 24 px | Кнопка «Меню» |
| От 1200 px | Не менее 48 px | 12 | 32 px | Полное меню |

Максимальная ширина внутреннего контента — **1280 px**, по центру. Она включает колонки и межколонники, но не внешние поля. Фактическая ширина — меньшая из 1280 px и ширины viewport за вычетом двух внешних полей. На 1440 px контент равен 1280 px и поля составляют 80 px; на 1920 px поля — 320 px.

Текстовый контейнер — до 680 px и дополнительно ограничен длиной строки. Для подробного кейса допустимо до 760 px при контроле набора. Изображение может занимать всю ширину внутреннего контейнера; фон раздела — всю ширину окна. Контент изображений не должен вплотную касаться края телефона.

Шаблоны desktop:

- Hero: 8 колонок текста + 4 колонки схемы; при тесном наборе схема уходит под текст.
- Заголовок и пояснение раздела: 5 + 7 колонок.
- Услуги: название 4, описание 5, ссылка 3 колонки.
- Работы: один проект на 12 колонок, затем два на 6 + 6; только если есть три содержательные работы.
- Контакт: вводный текст 5, форма 7 колонок.

На tablet hero и контакт могут становиться одноколоночными. На mobile весь содержательный порядок линейный. Дробная сетка помогает выравнивать элементы, но не требует сохранять несколько колонок текста на телефоне.

## 8. Геометрия и визуальные материалы

- Кнопки и поля: радиус 8 px. Превью проектов и самостоятельные поверхности: 12 px. Служебная метка типа работы: 4 px, без формы «таблетки».
- Линии — 1 px; декоративные border-subtle не имитируют функциональный контур.
- Тени в обычных секциях не используются. Модальное меню отделяется сплошной поверхностью и затемнением фона без свечения и размытия.
- Иконки — единое семейство контурных значков 20 или 24 px, толщина около 1,5–2 px. Иконка поддерживает подпись, а не заменяет понятный текст.
- Стрелки нужны только там, где уточняют действие; не добавлять их ко всем ссылкам автоматически.
- Не использовать стоковые фотографии «команды в офисе». Фото основателя или команды допустимо только реальное и с согласованной публикацией.
- Интерфейсы работ показывать фронтально и достаточно крупно, без наклонённых устройств, скрывающих содержание.

## 9. Кнопки и ссылки

| Компонент | Обычный вид | Размеры | Использование |
|---|---|---|---|
| Основная кнопка | Electric Blue, текст Obsidian, без свечения | Мин. высота 52 px desktop, 48 px mobile; горизонтальные поля 24 px | «Обсудить проект», «Отправить запрос» |
| Вторичная кнопка | Прозрачная, текст Primary, контур border-control | Та же высота, поля 24 px | Альтернативное действие в одной группе |
| Текстовая ссылка | Electric Blue, подчёркивание с отступом 3 px | Текст 16–18 px | Ссылки в тексте и на подробности |
| Пункт навигации | Primary Text, без постоянной рамки | Зона нажатия не менее 44 × 44 px | Переход между разделами сайта |
| Иконка-кнопка | Primary Text, контур при необходимости | Не менее 44 × 44 px | Закрытие меню и иные короткие действия |

Между соседними самостоятельными целями оставлять минимум 8 px. Ссылка внутри абзаца сохраняет естественную строку и отличается подчёркиванием. Текст кнопки не сокращается многоточием; высота растёт, если подпись переносится при увеличении текста.

Переход на страницу или к разделу оформляется как ссылка, даже если выглядит как кнопка. Кнопка выполняет действие: открыть меню, развернуть вопрос, отправить форму. Надпись описывает следующий шаг: «Подробнее о лендингах», а не одинаковое «Подробнее» без контекста.

Состояние посещённой текстовой ссылки: Secondary Text и сохранённое подчёркивание. Не менять вид основных CTA из-за истории посещений.

## 10. Состояния взаимодействия

| Элемент | Hover | Focus с клавиатуры | Active / pressed |
|---|---|---|---|
| Основная кнопка | Фон accent-hover, текст Obsidian | Внешний контур по общему правилу | Фон accent-pressed, без уменьшения масштаба |
| Вторичная кнопка | Подложка Graphite, светлый контур | Внешний контур | Подложка border-subtle, текст Primary |
| Текстовая ссылка | accent-hover, более заметное подчёркивание | Внешний контур, подчёркивание сохраняется | Основной accent, подчёркивание сохраняется |
| Навигация | Подчёркивание | Внешний контур | Текущий раздел отмечен постоянно, без сдвига текста |
| Карточка работы | Подчёркивание названия; изображение без обязательного zoom | Контур охватывает ссылку-карточку | Лёгкое изменение подложки подписи |
| Поле | Граница Primary Text | Контур accent, label остаётся видимым | Каретка и введённый текст; без изменения размеров |
| FAQ | Заголовок подчёркнут | Контур кнопки вопроса | Открытое состояние с меткой «Свернуть» или минусом |

**Общий фокус:** контур 3 px, отступ 3 px, без blur. На Obsidian и Graphite — Electric Blue. На синем фоне или рядом с насыщенным изображением — Primary Text с тёмным разделительным промежутком; проверить контраст с соседними цветами. Контур не обрезается краем карточки, overflow или окном.

Hover применяется только там, где устройство действительно поддерживает наведение. На touch все названия, действия и пояснения видимы сразу. Фокус может сосуществовать с hover и ошибкой; ошибка не должна убирать контур фокуса.

**Disabled:** не использовать как исходное состояние кнопки отправки ради обязательных полей. Дать отправить и объяснить ошибки. Во время запроса показывать «Отправляем…», не допускать повторной отправки, сохранять размеры и понятное состояние ожидания. Если действие недоступно по иной причине, рядом объяснить почему; не полагаться только на серый цвет.

**Selected и active — разные состояния:** нажатие кратковременно; текущая страница, выбранная опция и открытый вопрос сохраняют маркер до изменения выбора. Для навигации использовать также программное обозначение текущей страницы.

## 11. Карточки и страницы проектов

### Что показывает карточка

1. Крупное изображение интерфейса с зарезервированными пропорциями 16:10.
2. Название реального проекта либо ясное описание концепта.
3. Тип: «Лендинг», «Многостраничный сайт», «Веб-приложение».
4. Одно предложение о задаче и фактически выполненной работе.
5. Явная метка «Концепт» или «Собственный проект», если это не клиентский заказ.

Подпись расположена под изображением, а не появляется поверх него при hover. Превью не закрывается затемняющим слоем с единственной кнопкой. Карточка не содержит неподтверждённых метрик.

Главная работа — на всю ширину; дополнительные — по две, если изображения остаются читаемыми. Внутри превью допускается нейтральная подложка, подобранная под конкретную работу, без навязанного синего фильтра. Обрезка сохраняет главный экран и смысл; для узких экранов готовится отдельный кроп или мобильный экран. Если изображение отсутствует, использовать честное текстовое представление, а не пустую «картинку-заглушку».

Если карточка целиком ведёт на кейс, это одна ссылка с понятным названием, без вложенных кнопок. Отдельный переход на запущенный сайт размещается уже на странице проекта. У содержательного изображения есть краткое текстовое описание; если оно только дублирует название и соседнее описание, не заставлять скринридер читать одно и то же дважды.

### Правило честного портфолио

На старте реальные клиентские работы не предоставлены. Базовая главная не предполагает их существования. Раздел работ подключается только после подготовки материалов, которые можно показывать.

- Реальный кейс: задача, роль NOVARY, состав работ, процесс, результат без вымышленных показателей, разрешённые изображения.
- Концепт: заметная метка и фраза «Демонстрационная работа, не клиентский заказ». Описывать замысел и реализованный объём; не утверждать запуск или влияние на бизнес.
- Пока нет ни кейсов, ни готовых концептов, блок работ и пункт навигации скрыты. Их место занимают услуги и подход; не публиковать «Скоро здесь появятся проекты».

## 12. Разделы и визуальная иерархия

| Тип раздела | Форма | Смысл |
|---|---|---|
| Hero | Самый крупный текст, короткое объяснение, одна группа действий | Кто вы и чем полезны |
| Проекты, когда готовы | Крупные изображения и короткие подписи | Что можно оценить глазами |
| Услуги | Три горизонтальные строки на desktop, последовательные блоки на mobile | Какой формат подходит |
| Процесс | Четыре последовательных этапа с результатом каждого | Как проходит работа |
| Подход к AI | Открытый текст и компактные смысловые строки | Как используется технология и где контроль |
| FAQ | Вопросы с раскрываемыми ответами | Снять сомнения до обращения |
| Контакт | Сильный короткий заголовок и простая форма | Начать разговор |

Нумерация допустима у этапов процесса, поскольку порядок имеет значение. Услугам, преимуществам и проектам порядковые номера не нужны.

На каждом участке один визуальный центр. H2 сильнее H3, H3 сильнее подписи. Важная информация не прячется в самом бледном цвете. Основной CTA сильнее вторичного; служебная ссылка слабее обоих. Размер, расположение и отступы создают иерархию раньше цвета.

Graphite применяется для конкретного функционального объединения — например, формы или меню. Не чередовать фоны автоматически через раздел. Разделитель нужен при реальном переходе между темами, а не после каждого абзаца.

## 13. Анимации и переходы

Образ движения: короткое, спокойное подтверждение действия пользователя. Основной сайт полностью понятен в статике.

| Сценарий | Длительность | Поведение |
|---|---:|---|
| Цвет кнопки, ссылки, границы | 120–160 мс | Плавное изменение без задержки реакции |
| Нажатие | 80–100 мс | Смена цвета, без пружины и подпрыгивания |
| Открытие меню | 180–240 мс | Прозрачность и смещение до 8 px, закрытие быстрее |
| Раскрытие FAQ | 160–200 мс | Контент не ждёт длинной анимации; допустимо мгновенное раскрытие |
| Необязательный вход схемы hero | 300–450 мс, один раз | Изменение прозрачности/смещения до 8 px; текст уже доступен |

Характер easing: мягкое замедление, ориентир cubic-bezier(0.2, 0.7, 0.2, 1). Никаких упругих отскоков, длинного инерционного движения и покадровой анимации букв. Анимировать прежде всего transform и opacity; избегать тяжёлого перерасчёта геометрии.

Не анимировать появление каждой секции по скроллу. Не делать весь текст невидимым до срабатывания эффекта. Не использовать бегущие строки и автоматическое видео. Схема hero не обязана двигаться; статическая версия — полноценный основной вариант.

При пользовательской настройке reduced motion: убрать входные смещения, параллакс и плавную прокрутку; меню и FAQ меняют состояние сразу, информация остаётся доступной. Состояние загрузки сопровождается текстом и не зависит от вращающегося индикатора. Фокус показывается немедленно.

## 14. Адаптивное поведение

- Опорные ширины проверки: 320, 360, 390, 768, 1024, 1280, 1440 и 1920 px, а также промежуточные размеры.
- Приоритеты на mobile: кто и что делает → действие → примеры при наличии → услуги → процесс → вопросы → контакт.
- Hero не занимает принудительно весь экран. Высота зависит от текста; на коротком экране кнопка и контент доступны обычной прокруткой.
- Схема hero идёт после текста и CTA, упрощается до трёх понятных состояний. На 320 px достаточно подписей и простого схематического экрана.
- CTA на mobile может занимать всю ширину группы; вторичное действие — следующей строкой. На desktop кнопка не растягивается до всей колонки.
- Работы идут вертикально; горизонтальная карусель не требуется. Три услуги также идут по порядку без вкладок.
- Нельзя менять логический порядок чтения ради композиции. Нельзя скрывать условия и пояснения только потому, что экран узкий.
- Шапка: 80 px desktop и 64 px mobile при обычном размере текста; это минимальная, а не жёсткая высота. Сплошной фон, без стекла. Допустимо закрепление, если оно не перекрывает контент и фокус.
- Ниже 1200 px навигация открывается кнопкой «Меню». Панель показывает те же страницы и CTA; имеет видимую кнопку «Закрыть», поддерживает Escape, возврат фокуса и прокрутку на низком экране.
- Для модального меню фон недоступен взаимодействию, фокус остаётся внутри до закрытия. Меню не открывается от одного наведения.
- Учитывать системные безопасные области. Не добавлять постоянную нижнюю панель CTA, перекрывающую форму.
- Длинные ссылки, email, ошибки и заголовки переносятся без горизонтального скролла. Формы не требуют фиксированной высоты.
- Масштаб текста 200% и reflow на ширине 320 CSS px не должны приводить к потере функций. Изображения и сложные схемы имеют доступную текстовую альтернативу.

## 15. Формы и обратная связь

Форма обращения компактная: имя необязательно, один обязательный контакт, обязательное описание задачи. Бюджет, сроки, файл и телефон не требуются для первого сообщения. Детальная спецификация и тексты состояний — в HOMEPAGE_STRUCTURE.md.

- У каждого поля постоянная видимая подпись, а не только placeholder. Обязательность указана словами или расшифрованным знаком.
- Поле: Graphite, текст Primary, контур border-control, минимум 52 px по высоте. Многострочное поле — от 144 px, с возможностью увеличения.
- Подсказка находится рядом с полем и не содержит критичной информации только в tooltip.
- Проверять данные после выхода из изменённого поля либо после попытки отправки, не показывать ошибку до начала ввода.
- Ошибка: контур status-error, конкретный текст под полем, связь ошибки с полем для вспомогательных технологий.
- После неуспешной отправки переводить внимание к первой ошибке или доступному списку ошибок; введённые данные сохраняются.
- Во время отправки показывать понятный статус. При технической ошибке оставить возможность повторить действие и использовать подтверждённый прямой контакт.
- Успех показывать только после подтверждения приёма запроса сервером; не обещать обработку, если отправка не подключена.
- Сообщение об успехе остаётся доступным, объявляется скринридеру и не исчезает по таймеру.
- Согласие, если оно предусмотрено согласованным процессом обработки данных, не отмечено заранее; документы открываются без потери заполненной формы. Финальные формулировки и реквизиты предоставляет владелец студии.

## 16. Доступность и критерии качества

Цель будущей реализации — WCAG 2.2 AA. Документ задаёт требования, но сам по себе не подтверждает соответствие сайта. Базовый источник: [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

| Область | Критерий приёмки |
|---|---|
| Контраст | Используются проверенные пары; функциональные границы, значки и состояния различимы с контрастом не ниже 3:1 к соседнему фону |
| Клавиатура | Всё доступно без мыши; порядок предсказуем; есть переход к основному содержимому; отсутствуют ловушки вне управляемого модального меню |
| Видимый фокус | Контур не убирается и не обрезается; шапка, меню и уведомления его не перекрывают |
| Размер целей | Внутренний стандарт NOVARY — минимум 44 × 44 px для самостоятельных контролов, основные кнопки от 48 px по высоте |
| Масштаб и reflow | Текст увеличивается до 200%; при 400% на исходном окне 1280 px получается читаемый поток около 320 CSS px без двухмерной прокрутки обычного контента |
| Чтение | Один основной заголовок, последовательные уровни, понятные подписи, язык страницы русский, английский слоган отмечен как английский |
| Изображения | Смысловые изображения имеют альтернативу, декоративные исключены из чтения; текст интерфейса не заменён картинкой |
| Цвет и состояния | Ошибка, выбор, ссылка и успех имеют нецветовой признак |
| Формы | Подписи и ошибки связаны с полями; статусы отправки доступны скринридеру; ввод не теряется |
| Движение | Уважается reduced motion; нет вспышек, автозвука и обязательного движения |
| Указатель | Hover не открывает единственный путь к информации; всё работает на touch и с клавиатуры |
| Интервалы текста | Пользовательские увеличения межбуквенных и межстрочных расстояний не обрезают текст и кнопки |

Стандарт проекта 44 × 44 px строже минимума 24 × 24 CSS px с оговорёнными исключениями в [WCAG 2.2, размер цели AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Не выдавать 44 px за обязательный минимум AA.

Аналогично, AA требует не скрывать сфокусированный элемент целиком; NOVARY принимает более удобное внутреннее правило — элемент и его контур видны полностью. Различие объяснено в [W3C, Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).

При реализации проверять не только автоматическим анализатором: пройти сайт клавиатурой, проверить mobile с touch, масштабирование, reduced motion и хотя бы один скринридер. В текущем этапе эти проверки не выполняются, поскольку интерфейс ещё не создан.

## 17. Распространение на многостраничный сайт

Общие компоненты: шапка, мобильное меню, навигация, футер, кнопки, поля, служебные сообщения, карточка работы, строка услуги, блок этапа, FAQ и контактный блок.

Общие шаблоны:

- Страница услуги: H1 → кому подходит → состав работ → границы услуги → процесс → вопросы → контакт.
- Страница проекта: H1 и статус → задача → роль NOVARY → решения → экраны → фактический результат → контакт.
- Страница студии: позиционирование → реальные люди при наличии материалов → подход к работе и AI → контакт.
- Контакты: способы связи и форма без отвлекающих декоративных блоков.
- Правовые документы: спокойный текстовый шаблон, короткая строка, обычные ссылки, без Display-типографики.

На внутренних страницах меняется содержательная композиция; токены и поведение сохраняются. Услуга не копирует главную с тем же hero и одинаковым набором карточек.
